# バックエンドと画面の対応表

確認日：2026年9月23日

現在の業務用コントローラーに対し、一般会員向けの購入フローと管理者向けの操作画面を接続した。
画面・入力エラー・確認ダイアログ・Element Plus の標準表示は日本語とする。
商品名や説明など、データベースに保存された任意の入力内容は翻訳しない。

## API と画面

API のパスはすべて `/api` を基点とする。

| 機能 | API | 画面 | 利用者 |
| --- | --- | --- | --- |
| ログイン・本人情報取得 | `POST /auth/login`、`GET /auth/me` | `/login`、共通の認証処理 | 未ログイン／本人 |
| 会員登録 | `POST /members` | `/register`、管理画面の会員登録 | 未ログイン／管理者 |
| 本人情報の編集 | `PUT /members/{id}` | `/profile` | 本人 |
| 商品検索・ページ切替 | `GET /products/search` | `/products/search` | ログイン済み会員 |
| 商品詳細 | `GET /products/{id}` | `/products/:id` | ログイン済み会員 |
| カート表示・全削除 | `GET /cart`、`DELETE /cart` | `/cart`、注文確認、件数表示 | 本人 |
| カート追加 | `POST /cart/items` | 商品一覧・商品詳細 | 本人 |
| 数量変更・商品削除 | `PUT /cart/items/{productId}?quantity=`、`DELETE /cart/items/{productId}` | `/cart` | 本人 |
| 注文作成 | `POST /orders` | `/checkout` | 本人 |
| 注文履歴・明細 | `GET /orders`、`GET /orders/{id}` | `/orders`、`/orders/:id` | 本人 |
| 模擬決済 | `POST /orders/{id}/pay` | 注文詳細 | 本人 |
| 商品一覧・登録・編集・削除 | `GET/POST /products`、`GET/PUT/DELETE /products/{id}` | `/admin/products` | 管理者（書き込み） |
| 商品の公開状態・在庫変更 | `PUT /admin/products/{id}/status?status=`、`PUT /admin/products/{id}/stock?stock=` | `/admin/products` | 管理者 |
| 全会員一覧・詳細・編集・削除 | `GET /admin/members`、`GET/PUT/DELETE /members/{id}` | `/admin/members` | 管理者 |
| 会員の権限変更 | `PUT /admin/members/{id}/role?role=` | `/admin/members` | 管理者 |
| 全注文一覧・状況変更 | `GET /admin/orders`、`PUT /admin/orders/{id}/status?status=` | `/admin/orders` | 管理者 |

`GET /members` は `GET /admin/members` と同じ会員一覧を返すため、画面では管理者用 API に統一した。
サンプル用の `GET /map` は EC 業務の画面には追加していない。

## 仕様上の注意

- 商品検索のカテゴリは完全一致。キーワード、最低価格、最高価格、ページ番号、表示件数を送信する。
- 商品閲覧にも、現在のバックエンド設定に合わせてログインが必要。
- 管理画面は `GET /auth/me` が返す `ADMIN` 権限で表示する。URL の直接入力と API の直接呼び出しも別々に制限する。
- 通常の会員登録では管理者権限を指定できない。管理画面の確認には既存の管理者アカウントが必要。
- 会員情報のパスワード欄が空の場合は変更しない。管理者による商品・会員の削除は確認ダイアログを表示し、関連データがある場合はバックエンドの制約に従う。
- 注文金額は既存仕様どおり、カート追加時の価格を基準にする。現在の商品価格とは区別して表示する。
- カート全体を注文する仕様であり、商品を選択して一部だけ注文する API はない。
- 管理者の注文一覧 API は注文明細を返さない。管理画面には注文番号・会員番号・日時・合計・配送先・状況を表示し、他人の明細を本人用 API で取得しない。
- 決済 API はモックであり、決済代行サービスとの連携や実際の返金は実装されていない。
- 管理者による注文状況の変更は、未払い → 支払い済み／キャンセル、支払い済み → 発送済み／キャンセル、発送済み → 完了に限定する。キャンセル済みの注文は再開できない。
- 未払いで15分を超えた注文は、稼働中の定期処理が約5分間隔で確認し、キャンセルする。画面上の状態は再取得時に反映される。

## 今回追加していない機能

一般会員による注文キャンセル、配送追跡、住所録、お気に入り、クーポン、画像アップロード、
メール認証・パスワード再発行、実決済・返金には対応 API がないため、未実装の機能を利用可能なボタンとして表示していない。

今回の対応は既存 API に対する画面の整備であり、上記の新規 API 開発や本番運用の完成を意味しない。
検証結果・変更理由・起動手順は [実装差分](IMPLEMENTATION_DIFF.md) を参照。
